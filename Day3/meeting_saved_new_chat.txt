	4. What if both agents are needed?
	The current notebook supports only one route:
	Coordinator -> Product Agent
	
	For a query like:
	“Is chicken available, and where is my order?”
	both agents are needed. A better design would be:
	Customer Query
	      |
	  Coordinator
	    /      \
	Product   Service
	 Agent     Agent
	    \      /
	   Final Answer Agent
	
	The Coordinator sends tasks to both agents. They produce separate results, and a final answer agent combines them into one clear response for the customer

2026-08-12 22:12:53 From shakti p - SME to Everyone:
	Replying to "Tangent: Since state is shared across multiple age...":
	As the workflow continues, state["messages"] can grow. Later agents may receive:
	The original customer query
	Previous worker answers
	Supervisor decisions
	Tool results
	Intermediate discussion
	This can cause context saturation. The model may lose focus, repeat work, or make weaker decisions.
	But shared state does not mean every agent must see everything. A better design is to give each agent only the information it needs

	A long graph with small, focused handoffs can work well. A short graph that passes the entire history everywhere can still suffer from context saturation

2026-08-13 00:25:42 From shakti p - SME to Everyone:
	Replying to "What kinds of cache can implemented for the agent?":
	An agent does not automatically have a useful application cache. You usually implement caching yourself.
	Common cache types:
	Tool-result cache: Store inventory, weather, or policy results for a short time.
	Response cache: Reuse the answer for the same query.
	Semantic cache: Reuse results for similar questions, not only identical text.
	Embedding cache: Avoid recalculating embeddings for the same document.
	Session/state cache: Keep conversation state during a session.
	Prompt cache: Some model providers cache repeated prompt content, but this is provider-managed and not a complete answer cache
